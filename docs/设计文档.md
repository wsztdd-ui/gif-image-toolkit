# 设计文档（GifKit）

版本：v0.4（按 2026-10-11「UI 简化易用」反馈修订）　日期：2026-10-11　状态：待最终确认

## 1. 技术选型

| 方案 | 体积 | 界面能力 | 开发效率 | 便携性 | 结论 |
|---|---|---|---|---|---|
| **Python + PySide6 + ffmpeg**（推荐） | 单文件约 60–80MB | Qt 成熟控件，拖拽/框选/滑杆齐全 | 高 | PyInstaller 单 exe | ✅ 采用 |
| Electron + ffmpeg | 150MB+，内存占用高 | 高 | 高 | 需打包器 | 体积过大 |
| C# WinForms/WPF + ffmpeg | 较小（需 .NET 自包含约 70MB） | 够用 | 中 | 可单文件 | 生态与 ffmpeg 交互不如 Python 顺手 |
| Tauri + ffmpeg | 最小 | 够用 | 低（需 Rust 工具链 + 前端） | 好 | 开发成本高 |

选型理由：GIF 生成本身完全交给 ffmpeg 子进程，Python 只做界面与调度；PySide6 对拖拽、图像上框选、后台线程支持成熟；PyInstaller 产物即绿色 exe，符合需求 4。

## 2. 总体架构

```
┌───────────────────────────── GifKit.exe ─────────────────────────────┐
│  main.py                                                             │
│  ┌──────────────── MainWindow（QTabWidget）───────────────────────┐  │
│  │  GifTab（视频转GIF）              │  ImageTab（图片压缩）       │  │
│  │  ├ CropPreview 预览/框选控件      │  ├ 文件列表表格             │  │
│  │  ├ 时间选取（滑杆+数值+缩略图）    │  ├ 参数区（格式/质量/尺寸） │  │
│  │  └ 参数区/预估/进度               │  └ 压缩进度/结果对比        │  │
│  └────────────────────────────────────────────────────────────────┘  │
│            │ QThread 后台工作者（界面永不卡顿）                        │
│  ┌─────────┴───────────────────────────────────────────────────┐     │
│  │ core/（纯逻辑层，不依赖 Qt，可独立测试）                      │     │
│  │  ffmpeg.py  —— ffmpeg/ffprobe 子进程封装、进度解析、GIF两遍法 │     │
│  │  imglib.py  —— Pillow 压缩（格式/质量/缩放/量化）             │     │
│  └──────────────────────────────────────────────────────────────┘     │
│  utils/config.py —— 便携配置 config.json（程序目录优先）              │
└──────────────────────────────────────────────────────────────────────┘
        │ 调用（子进程，CREATE_NO_WINDOW 不弹黑框）
   bin/ffmpeg.exe   bin/ffprobe.exe   ← 随包内置，查找顺序: 程序目录bin → PATH
```

关键设计点：

- **核心层不依赖 Qt**：`core/` 是纯 Python 模块，可直接用脚本做无界面回归测试（生成测试视频 → 跑完整 GIF 管线）。
- **所有耗时操作走 QThread**：探测信息、提取缩略图、取帧预览、生成 GIF、批量压缩均为后台工作者，通过信号更新进度条，界面零卡顿。
- **ffmpeg 查找顺序**：`程序目录\bin\ffmpeg.exe` → `PATH`。便携包内自带，因此换机可用。

## 3. GIF 生成方案（两遍调色板法）

单遍直接转 GIF 色彩失真严重（只有 256 色全图共用）。采用业界标准两遍法：

**第一遍：统计最优调色板**（针对运动画面 `stats_mode=diff`）

```
ffmpeg -hide_banner -nostats -loglevel error -progress pipe:1
  -ss {起点} -t {时长} -i 输入.ts
  -vf "crop={w}:{h}:{x}:{y},scale={宽度}:-2:flags=lanczos,fps={帧率},
       palettegen=max_colors={颜色数}:stats_mode=diff"
  -update 1 -y palette.png
```

**第二遍：按调色板成图 + 抖动**

```
ffmpeg ... -ss {起点} -t {时长} -i 输入.ts -i palette.png
  -filter_complex "[0:v]crop=...,scale=...,fps=...[v];
                   [v][1:v]paletteuse=dither={bayer:bayer_scale=3|floyd_steinberg|none}[out]"
  -map "[out]" -loop 0 -y 输出.gif
```

参数映射：

| 界面参数 | 映射 |
|---|---|
| 裁剪范围 | `crop=w:h:x:y`（预览框选坐标原样换算到源视频像素） |
| 宽度 | `scale={W}:-1:flags=lanczos`（高度自适应；**GIF 无偶数尺寸限制，用 -1 保留奇数高度**，默认 720 宽 16:9 源精确输出 720×405） |
| 帧率 | `fps={N}`，自由输入 3–30（最小 3 由输入框下限保证） |
| 颜色数 | `palettegen=max_colors={N}` |
| 抖动 | `paletteuse=dither=bayer:bayer_scale=3 / floyd_steinberg / none` |

- 进度解析：ffmpeg 加 `-progress pipe:1`，从 stdout 读 `out_time=`，按已处理时长 ÷ 目标时长换算百分比（第一遍占 45%，第二遍占 55%）。
- `-ss` 置于 `-i` 前 = 快速定位（seek 到关键帧后解码对齐），GB 级 TS 也能秒级开截。
- **动图 GIF 再压缩**：同一管线，输入换成 `.gif` 即可（ffmpeg 原生逐帧读取 GIF）。拖入 .gif 时探测帧数与时长，界面隐藏"起点秒"改为显示"丢弃前 N 帧/保留时间范围"，其余参数（宽度/帧率/颜色/抖动/裁剪）全部可用；降帧抽帧即压缩体积的主要手段。
- 体积预估（界面实时显示，标注"粗略估算"）：
  `字节 ≈ 宽 × 高 × fps × 时长 × 系数(抖动) × 颜色系数`，误差约 ±40%，以实际生成为准。

### 3.1 输出预览流程（v0.2 新增）

```
调整参数 ──► [生成预览] ──► 后台两遍法生成到 临时目录\GifKit_preview\xxx.gif
                                  │
                    进度条 + 可取消（与正式生成同一管线）
                                  ▼
              预览区用 QMovie 内嵌循环播放 + 显示实际体积/尺寸/时长
                    │                       │
              [保存]                  [重新调整]
            移动到输出目录              丢弃临时文件，继续改参数
```

- 预览产物与最终保存产物**逐字节一致**（同一命令，只是落盘位置不同），预览体积即最终体积，不额外增加一次生成成本。
- 临时预览文件在关闭窗口/重新预览时自动清理。
- 帧率越小预览生成越快，建议先用高压缩档快速预览，满意后切高质量档出成品。

## 4. 裁剪交互设计（CropPreview 控件）

- 预览帧按窗口等比缩放居中显示；控件内部维护 `显示坐标 ↔ 视频像素坐标` 的线性映射（缩放比 = 源宽 / 显示宽）。
- 裁剪框以**视频像素坐标**存储，换分辨率/换帧后仍准确。
- 鼠标交互：空白处按下拖出新框；框内拖动 = 移动；四角手柄 = 缩放；比例锁定时缩放围绕对角锚点计算，越界自动收缩。
- 框外区域加半透明遮罩，框上角实时显示 `宽×高` 像素值。
- 更换起点帧时保留裁剪框（自动裁回画面范围内），方便跨时间核对选区。

## 4.1 UI 设计（v0.3，Microsoft Fluent 2 浅色）

按用户要求参照 [Fluent 2 设计系统](https://fluent2.microsoft.design/design-tokens) 重设计，弃用暗色方案：

| Token | 值 | 用途 |
|---|---|---|
| 品牌主色 | `#0F6CBD`（hover `#115EA3`、按下 `#0C3B5E`、选中底 `#EFF6FC`） | 主按钮、选中态、滑块、页签下划线 |
| 圆角 | 控件 4px、卡片 8px | 全部控件 |
| 描边 | 1px `#D1D1D1`，分隔线 `#E0E0E0` | 输入框/按钮/卡片 |
| 背景/卡片 | 窗口 `#F9F9F9`、卡片 `#FFFFFF` | 分层 |
| 文字 | 主 `#242424`、次 `#616161`、禁用 `#BDBDBD` | 层级 |
| 状态色 | 成功 `#0E700E`、警告 `#BC4B09`、错误 `#C50F1F` | 估算/提示/失败 |

- **字体**：思源黑体（Source Han Sans CN）Medium（Qt weight 500，"中等偏粗一点点"）；字体文件随包内置 `fonts\`，启动时 `QFontDatabase.addApplicationFont` 加载，回退系统思源黑体 → 微软雅黑。
- **时间选取**：自绘 `RangeSlider` 双滑块单滑轨（左=起点、右=结束、中间按住整体平移、点轨道跳最近滑块），配数字框精确输入。
- 视频预览区保持深色底（视频画面观感），卡片与控件全部浅色。

## 4.3 UI 简化（v0.4，2026-10-11 反馈；已在 v0.3.0 实现）

目标：默认路径零学习成本——**拖进来 → 选个质量档 → 生成 → 保存**，专业参数折叠进"高级"。只动布局与文案，不改核心逻辑、不改 config 字段，老配置升级后仍然生效。

1. **空状态即拖放区**：两页未载入文件时，主区域整块显示虚线拖放提示（"把视频/图片拖到这里，或点击选择"），点击唤起文件选择框；删除视频页独立的"选择视频…"按钮（图片页保留列表下方"添加图片…"）。
2. **高级参数折叠**：
   - GIF 页默认只露「质量预设 + 宽度」；帧率 / 颜色数 / 抖动 / 文件后缀收进「高级参数」折叠区，预设联动逻辑不变。
   - 图片页「PNG 256 色量化」「自动跳过反而变大」收进「高级选项」，默认值不变（量化开、跳过开）；后缀同样收进。
3. **输出位置一行化**：默认一行小字「保存到：和源文件相同的位置 ▸」，点"更改"才展开目录单选与路径框；`outdir_mode / outdir` 字段不变。
4. **文案减负**：GroupBox 标题去教学括号（「截取时间」「裁剪」「输出」），操作说明改为控件下方 12px 灰字；体积估算简化为「约 1.65 MB · 720×405」（悬停提示"粗略估算，以实际生成为准"）；源文件信息精简为一行（名称 · 大小 · 分辨率 · 时长），去掉编码字段与选区 x/y 坐标（裁剪仅显示"裁剪 960×540"）。
5. **生成结果卡片**：生成完成后为一张结果卡——动图预览 + 体积结论（动图再压缩显示「原 658 KB → 187 KB（-72%）」；视频截取显示「720×405 · 5.0s · 约 2.1 MB」）+ 大按钮「保存」；「重新调整」降为次要按钮，「打开目录」在保存后以链接出现。

## 4.4 功能升级（v0.5，2026-10-17）

四项并行的输出能力升级，全部落纯逻辑层（`core\ffmpeg.py` / `core\workers.py`）并带端到端测试：

1. **目标体积模式**：输出组新增「☐ 压到指定体积 [N] MB」。语义 = 以面板参数为**质量上限只降不升**，搜索只动三档：帧率（30→…→6）→ 颜色数（256→…→32）→ 宽度（1920→…→240）；按"实测/目标"比例跳档（体积 ≈ ∝帧率 ∝像素量，各分担 √r；颜色更激进），最多 4 轮，每轮完整两遍调色板编码取实测值。命中即停；到下限仍超返回最小一轮并黄字提示。`make_gif` 返回 `(path, applied)`，`GifWorker.ok` 同步 `(path, secs, dict)`；进度按预估轮数均分，取消贯通。配置新增 `target_mode / target_mb`。
2. **隔行源自动去隔行**：`probe` 新增 `field_order`；`auto` 模式下 `field_order ∈ {tt,bb,tb,bt}` 时链首插 `yadif=0:-1:0`（在 crop/scale 之前）；成品/静态帧/选段播放三条路径同一判定，所见即所得。「高级参数」新增「隔行源」下拉（自动/强制/关闭），配置 `deinterlace`。
3. **图片批量并行 + 取消**：`ImgWorker` 改 `ThreadPoolExecutor(min(6, cpu))`，行号随 `row` 信号走（乱序完成不串行），任务开头检查取消；状态行新增「取消」按钮，取消后已完成文件保留。
4. **估算试编校准**：两级估算——参数变化立即显示公式"粗估"，800ms 防抖后后台按当前完整参数试编选段 1 秒（选段 ≤1.2s 编全段）线性外推为"实测"（实测 content 相关误差从 ±40%+ 降到 ~5%）。代数防护复用既有模式；目标体积模式下不跑校准。

## 5. 图片压缩方案（Pillow）

| 场景 | 处理 |
|---|---|
| JPEG 输出 | `quality=q, optimize, progressive`；先按 EXIF 方向摆正 |
| WebP 输出 | `quality=q, method=6`（最高压缩努力级别） |
| PNG 输出 | 可选 `quantize(256色, 自适应调色板)`，截图类通常省 50%+；不量化则 `optimize=True` |
| 尺寸限制 | 最长边超限时 LANCZOS 等比缩小，只缩不放 |
| 格式转换 | 输出格式选 JPEG/WebP/PNG 即互转（PNG→JPG、JPG→WebP、BMP→PNG 等），转换本身即需求，质量滑杆 100 时近似无损转换 |
| BMP/TIFF | "保持格式"模式下转 PNG（本身无损且更小） |
| 变大保护 | 同格式压缩后反而变大 → 跳过写盘，列表标注 |

## 6. 打包与绿色便携

两种形态，构建脚本都提供（`build.bat` / `build.bat onedir`）：

| 形态 | 产物 | 特点 |
|---|---|---|
| 单文件版 | `GifKit.exe`（约 60–80MB） | 单文件拷走即用；首次启动自解压约慢 1–3 秒 |
| 文件夹版 | `GifKit\GifKit.exe` + 依赖 | 启动快；整个文件夹压缩包即绿色版 |

- ffmpeg/ffprobe 通过 PyInstaller `--add-binary` 打进包内（运行时解到 `bin/`）。
- 运行期只写 `config.json`（程序目录，只读则回退 `%APPDATA%\GifKit`），不写注册表、不留垃圾。
- 全部子进程调用加 `CREATE_NO_WINDOW`，GUI 模式不弹黑色控制台窗口。
- 杀软误报：PyInstaller 单文件 exe 偶有误报，文档中附说明与文件夹版备选；如需分发可加代码签名（可选，暂不做）。
